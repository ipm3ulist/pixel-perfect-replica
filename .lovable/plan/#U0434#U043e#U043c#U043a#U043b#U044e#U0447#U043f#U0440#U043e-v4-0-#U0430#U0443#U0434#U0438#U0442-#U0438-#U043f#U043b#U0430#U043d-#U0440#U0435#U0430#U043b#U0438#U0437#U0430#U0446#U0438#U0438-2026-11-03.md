# ДомКлючПро v4.0 — аудит и план реализации

## 1. Аудит ZIP (проверено фактически)

- Текущий проект в Lovable — пустой шаблон. Наработки есть только в ZIP: их нужно перенести сюда без изменений (шаг 0).
- Стек тот же: TanStack Start + Nitro (Cloudflare), package.json совпадает с шаблоном полностью.
- Тесты запущены на копии ZIP: 3 файла, 30 тестов — все прошли (16 тестов калькулятора обоев, 13 маршрутов, 1 базовый).
- Сборка ZIP отдельно не запускалась — проверю после переноса.

Существующие страницы (12 + инструкции):
`/`, `/kvartiry`, `/doma`, `/stroitelstvo`, `/remont`, `/materialy`, `/kalkulyatory`, `/kalkulyatory/oboi`, `/instruktsii`, `/instruktsii/$slug` (3 инструкции), `/spravochnik`, `/poisk`, `/o-proekte`, `/sitemap.xml`.

Контент: 5 разделов по 5–6 тем (`sections.ts`), 3 инструкции, ~17 терминов, 3 изображения (дом, материалы, поклейка обоев). Поиск — простой, без фильтров.

Пробелы по ТЗ:
- Нет категорий и подкатегорий со своими URL — «Квартиры»/«Дома» сейчас одна страница с темами.
- Нет хлебных крошек, canonical, Schema.org, мегаменю.
- Нет единой модели статей (поля tags, relatedContent, published, seoTitle и т.д.).
- Мало контента: нужно ≥25 статей, ≥30 терминов, 5–8 материалов.
- Sitemap собирает URL вручную — нужно генерировать из данных (только published).
- robots.txt без ссылки на sitemap.
- Нет блока партнёрских ссылок и точек аналитики.

GitHub Pages: проект собирается как серверное приложение (Nitro/Cloudflare), sitemap — серверный маршрут. Прямой совместимости с GitHub Pages нет. Минимальный путь — отдельная проверка статического пререндера на этапе 11; до этого архитектуру не меняем, рабочая публикация — через Lovable.

## 3. Этапы (каждый — отдельный запрос с отчётом)

0. Перенос ZIP в проект, сборка и тесты.
1. Модель данных: категории, статьи, материалы, термины, теги, калькуляторы (единые типы).
2. Навигация: мегаменю на десктопе, мобильное меню, хлебные крошки, блок выбора на главной.
3. Хабы «Квартиры» и «Дома» + 22 страницы категорий (сначала без новых изображений).
4. Изображения, партия 1 (10–12): главная, квартиры, дома, строительство, ремонт, материалы, планирование, стены, полы, ванная, фундамент, кровля. Генерирую только после вашего согласия со структурой.
5. Статьи, партия 1 (~12), затем партия 2 (~13) и материалы (8).
6. Справочник до 30+ терминов, поиск с фильтрами и типами контента.
7. Калькулятор обоев: граничные случаи, мобильный вид.
8. SEO: canonical, Open Graph, Schema.org (WebSite, BreadcrumbList, Article, HowTo), sitemap из данных, robots, инструкции для Яндекс Вебмастера и Search Console.
9. Монетизация: компонент «Что понадобится» с пометкой о партнёрской ссылке (пока пустой — без выдуманных магазинов), места под рекламу в длинных статьях, события аналитики без персональных данных.
10. QA: 360/390/430 px, клавиатура, контраст; проверка GitHub Pages; README; ZIP.

## 4. Недостающие компоненты

Breadcrumbs, MegaMenu, MobileNav, DirectionChooser (главная), HubPage, CategoryPage, ArticlePage, MaterialPage, RelatedContent, StartHereBlock, MistakesBlock, ComparisonTable, Callout (предупреждение), StepList, FAQ (только реальные вопросы), SearchFilters, PartnerBlock (с маркировкой), AdSlot (отключён), analytics `track()`, SEO-хелпер `buildHead()` (canonical, OG, JSON-LD), генератор sitemap из данных.

## Технические детали

- Данные: `src/data/categories.ts`, `articles/*.ts`, `materials.ts`, `glossary.ts`, `calculators.ts`, `tags.ts`; тип `Content` с полями из ТЗ; `relatedContent` — по slug, проверка ссылок тестом.
- Маршруты: `kvartiry.index.tsx` + `kvartiry.$category.tsx`, аналогично `doma`; `stati.$slug.tsx`; `materialy.$slug.tsx`. Неизвестный slug → `notFound()`.
- Изображения: WebP через imagegen → `src/assets/`, первое на странице — `fetchpriority="high"`, остальные `loading="lazy"`.
- Тесты: целостность данных (уникальные slug/title, рабочие related), sitemap только published, существующие 30 тестов сохраняются.
- Цифры/нормативы не придумываются: где значение зависит от проекта — так и пишется.
