# ДомКлючПро v8.0 — аудит и план подготовки к GitHub Pages

## 1. Аудит: что уже есть

- **Структура сохранена:** 36 страниц-маршрутов (квартиры, дома, 21 помещение, статьи, материалы, калькуляторы, инструкции, справочник, каталог, регионы, документы, поиск, сравнения, заявка, реклама).
- **Контент:** единая модель `src/content/*` (32 статьи, 8 материалов, 35 терминов, 11 из 20 изображений), проверка целостности `validateContent()`.
- **Калькуляторы:** обои, краска, плитка, ламинат, блоки, бетон, утеплитель — формулы чистые и покрыты тестами.
- **Дом:** конфигуратор `/doma/konfigurator`, смета `/doma/smeta` (только объёмы, цены выключены), проекты `/doma/proekty`, сохранение параметров в браузере.
- **Монетизация:** модель партнёров и рекламы (ERID обязателен), по умолчанию выключена; форма заявки выключена.
- **SEO:** `pageHead()` (canonical, OG, Schema.org), sitemap и robots из модели, фавиконы есть.
- **Проверки:** 12 наборов, 107 тестов — все проходят.

## 2. Аудит: что не готово или работает неправильно

1. **GitHub Pages — главный блокер.** По README (проверка 3 ноября) статически собиралась только главная; остальные страницы попадали в цикл перенаправлений (слэш в конце адреса). В репозитории нет workflow публикации, нет `404.html`, нет `.nojekyll`. Базовый путь `/pixel-perfect-replica/` задан только для ресурсов Vite — роутер, ссылки `urlFor()`, canonical, sitemap и пути к картинкам/фавикону его не учитывают.
2. **Динамические страницы** (`/stati/$slug`, `/kvartiry/$category`, `/kalkulyatory/$slug` и др.) должны получить явный список адресов для пререндера из модели контента, а не надеяться на обход ссылок.
3. **sitemap.xml и robots.txt** сейчас серверные маршруты — для статики их нужно генерировать файлами при сборке.
4. **Остатки серверной части** (`src/integrations/supabase/*`, `src/server.ts`) в статической версии не работают; формы и всё, что их использует, должны оставаться выключенными без ошибок в консоли.
5. **Роадмап v7/v8:** каталог компаний, партнёрский каталог товаров, финансирование, аналитика событий — не начаты. Сохранение заявок (Этап 1 ТЗ) без базы невозможно — по вашему условию остаётся выключенным.
6. **Изображения:** 9 из 20 тематических картинок отсутствуют; нужна проверка размеров и `loading="lazy"`.
7. **Не проверено:** мобильное меню на реальных ширинах, 404 на всех ветках, дубли заголовков H1, битые внутренние ссылки.

## 3. План по этапам (каждый — отдельно, с тестами и отчётом)

### Этап A. GitHub Pages (первым, т.к. главная цель)
- Единый базовый путь: `src/lib/base.ts` (читает `import.meta.env.BASE_URL`), подключить в `src/router.tsx` (`basepath`), `src/content/urls.ts`, `src/lib/seo.ts`, `src/lib/sitemap.ts`, `src/routes/__root.tsx` (фавикон, og-image).
- Исправить цикл перенаправлений: единая политика слэша в `src/router.tsx` (`trailingSlash`) и в `vite.config.ts`.
- `vite.config.ts`: список `pages` строится из модели контента (`src/lib/prerender-pages.ts`), чтобы все статьи, категории, помещения, калькуляторы рендерились в HTML.
- Статические `sitemap.xml`/`robots.txt` при сборке; `404.html` (копия страницы «Не найдено»), `public/.nojekyll`.
- `.github/workflows/deploy-pages.yml`: установка, тесты, сборка с `GITHUB_PAGES=true`, публикация папки клиентской сборки.
- Проверка: локальная сборка в отдельной копии, подсчёт отрендеренных HTML, просмотр в Playwright с подпапкой `/pixel-perfect-replica/` — переходы, картинки, 404, консоль.

### Этап B. Полезный функционал без backend
- Каталог компаний `/kompanii`, `/kompanii/$kategoriya`: 11 категорий, описание тарифов размещения, пустое состояние «Компании проходят модерацию» — без вымышленных фирм. Файлы: `src/data/companies.ts`, `src/routes/kompanii.index.tsx`, `kompanii.$kategoriya.tsx`.
- Партнёрский каталог товаров: структура 13 категорий в `src/monetization/data/`, карточка без товаров до появления реальных предложений с ERID; ссылки через единый `goLink()`.
- Сравнения материалов: дополнить `sravnenie.$slug` из существующих материалов.
- Связка калькуляторов и комнат с будущей заявкой: передача параметров расчёта в `/zayavka` через адрес — форма показывает «приём откроется позже», ничего не отправляет.
- Калькуляторы второй очереди (кровля, стяжка, площадь стен, объём помещения) — только по проверяемым формулам, с тестами.

### Этап C. Страницы, навигация, SEO, дизайн
- Проверка мобильного меню и всех страниц на 375/768/1280.
- Новые разделы в меню и подвале (`src/data/site.ts`).
- Тест SEO: уникальные title/description, один H1, canonical на всех маршрутах.
- Логотип/фавикон: проверить набор (svg, ico, apple-touch-icon, manifest).

### Этап D. Техническая проверка
- Тесты, линтер, сборка для GitHub Pages, тест «нет битых внутренних ссылок» по sitemap, проверка картинок и консоли.

### Этап E. Production
- Обновить README (раздел GitHub Pages), roadmap.md, AGENTS.md; итоговый отчёт: что работает статически, что требует сервера в будущем (заявки, учёт переходов).

## Технические детали
- Lovable Cloud и Supabase не подключаются; файлы интеграции остаются неактивными.
- Учёт переходов `/go/$id` на статике возможен только как клиентское событие аналитики после согласия — без сервера статистика неполная, это будет указано.
- Порядок: A → B → C → D → E, после каждого этапа — тесты, отчёт со списком файлов, обновление roadmap.md.
